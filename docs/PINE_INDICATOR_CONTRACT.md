# Pine 策略模型长期开发规范

本规范是用户已确认的项目约定。后续新指标开发自动沿用；用户只需提供本次策略逻辑，不需要重新复制开发提示词或重复定义通用输出属性。

## 1. 职责与适用范围

一个 Pine 指标是一个策略模型，负责行情计算、入场条件、方向、入场参考价及策略止损。
本项目是公共执行模型，负责输出校验、信号去重、风险定量、订单、成交、保护单与恢复。
不在 Python 中重新计算新策略的行情信号，也不以图形、颜色、标签文字替代数值接口。

首个已接入模型是用户自定义的 **EMA9-ST-ATR**。本规范依据其现有导出接口与公共执行契约整理，不代表仓库已经包含该私有指标的完整 Pine 源码。
不得把它误解为单独的 EMA9 均线，或在没有完整源码时猜测其全部算法。

## 2. 统一导出属性

新建指标使用 Pine Script v6 `indicator()`，按以下标题声明全局数值 `plot()`：

| 公共属性 | 标准 plot 标题 | 编码与要求 |
|---|---|---|
| `entry_signal` | `Entry_Signal` | 数字 `1` 有入场信号，`0` 无信号；多空均用 `1` |
| `direction` | `Direction` | `1` 多、`-1` 空、`0` 中性/未知；表示方向状态，不是入场脉冲 |
| `entry_price` | `Entry_Price` | 正的绝对入场参考价，计算方式由本策略规定 |
| `long_stop` | `Long_Stop` | 多头绝对止损价 |
| `short_stop` | `Short_Stop` | 空头绝对止损价 |
| 辅助 `atr` | `ATR` | 本策略所用 ATR；不使用时可为 `na`，不增加额外过滤 |

前五项是执行器必需的语义映射。新指标默认保留全部六个标准 plot，ATR 值不作为所有策略的强制交易条件。
单向策略也声明另一侧止损 plot，其值可以为 `na`。
标的、周期和 bar 时间由采集器获取，不要求另行导出时间 plot。

标题固定、唯一、使用 ASCII，不动态拼接、不随版本随意改含义。
使用 `display.data_window`、`offset=0`；不得仅在 `barstate.islast` 输出，或通过隐藏图表装饰同时关闭协议值。
图形显示与协议输出来自同一套计算结果；提醒和 `alertcondition()` 可选，不能代替 plot。

现有 EMA9-ST-ATR 的 `Touch_EMA9` 和 `EMA_9` 分别映射为公共入场信号与入场价；保持已发布名称和兼容标识，不为新规范擅自更名。

## 3. 完整性与价格语义

- `Entry_Signal=1` 时，同一快照的方向、入场参考价与对应止损必须组成同一个有效计划。
- 多头必须满足 `0 < Long_Stop < Entry_Price`；空头满足 `Short_Stop > Entry_Price > 0`。
- 按 `syminfo.mintick` 处理价格精度，取整后再次校验严格大小关系。
- 入场依赖数据未就绪、非有限值、价格非法或止损方向错误时，信号为 `0`。
- 无入场信号不意味着方向消失；应继续输出该策略当时的方向状态。
- 明确无信号时入场参考价与止损的意义；跟踪止损可能在已有仓位成本的盈利侧，不能据此发布非法的新入场计划。
- Pine 不知道券商实际成交价、数量或成本，不把理论成交当成真实持仓。

## 4. 时间与重绘契约

本次需求必须明确实时触发还是收盘确认，以及触发后价格、止损是否锁定。

当前消费方式：实时快照用于入场；确认快照用于方向反转提醒和止损管理；不因方向反转自动平仓。
实时信号不能只存在于一个 tick 或 `barstate.isnew`；说明当根的保持、失效和反向处理。
收盘确认入场需要同时确认或扩展执行器消费方式，不能仅增加 `barstate.isconfirmed` 就声称已兼容。

不偷偷搬移上一根信号、不回填到过去、不通过绘图偏移制造提前信号。
禁止未来数据泄漏；高周期取值须交代确认时点，并正确处理 `request.security()` 的历史/实时差异。
未收盘值变化与收盘后历史重绘必须分别说明。
仅 OHLC 无法确定根内成交顺序，`varip` 的实时锁存也不能凭历史 OHLC 完整还原；不得承诺不存在的逐笔一致性。

## 5. 执行能力边界

Pine 信号触发的首仓和加仓统一使用**市价 MKT 入场 + STP 保护止损子单**，不把 `Entry_Price` 当成等待回踩的挂单限价。`Entry_Price` 仍是 Pine 的策略参考价，保留在订单计划中；数量和计划风险按触发时新鲜观察价到实际止损的距离估算，最终成交使用券商回报。市价可能滑点，实际成交风险不保证等于估算预算，也不承诺所有时段均立即成交；不会静默改回 LMT。时段、风控、去重及保护规则继续生效。

实盘、回测和夜盘模拟使用相同的显式 `entry_order_type=MKT` 声明；`limit_type=auto_<模型ID>` 只表示来源与归属，继续兼容恢复。手动限价入口保留原行为。已有 LMT 挂单不会因升级自动变为 MKT；核对、撤单等操作仍依据原订单事实。

模拟 MKT 按处理信号时的观察价成交，不等待回到 Pine 参考线。历史 OHLC 沿用既有极值路径，多头先取最高价、空头先取最低价，可能明显改变数量与回测结果；这是合成路径近似，不是实际根内信号发生价，也不代表已验证策略盈利。

| 输出或配置 | 当前含义 |
|---|---|
| `Entry_Signal=0` | 不发起新入场，不表示撤单或平仓 |
| `Direction=0` | 中性/未知，本身不触发强制退出 |
| 确认后的相反方向 | 仅提醒，由用户决定平仓；原保护止损继续有效。旧兼容开关不能启用自动反向退出 |
| 止损 `na` 或 `0` | 不代表撤销已有保护单 |
| `single_entry` | 基础单次建仓配置；成交后跟随确认止损收紧，无自动金字塔和自动保本 |
| `ema9_legacy_pyramid` | 保留已有 EMA9 金字塔、时段、加仓与保本规则的显式兼容配置 |

新指标不默认继承 EMA9 的 3-2-1 风险预算、2R 解锁、3R 保本或其他过滤。
独立退出、撤销挂单、分批止盈、复杂订单类型等需求，应明确输出扩展和执行端处理，不能仅添加 plot 就宣称已经支持。

## 6. 接入与交付

接入声明统一写入 `service/pine_strategies.json`：模型 ID、名称、真实指标 ID、独立实时/确认快照键、plots、fields、执行配置。
不要编造可用的指标 ID，不在未发布/未取得访问权限时注册假生产模型。
不同模型、执行实例、标的和交易轮次的订单与恢复状态必须隔离；账户风控统一汇总。

每次新指标开发应交付：

1. 策略规则、必要假设和时间语义。
2. 完整 Pine v6 源码，不留未定义变量或伪代码。
3. 六个 plot 的名称、取值、无效值及更新时机。
4. 对应模型声明片段；未发布 ID 明确待填。
5. 多空、无信号、未就绪、非法止损、实时失效、确认反向等场景自检。
6. TradingView 编译/图表验证步骤及重绘、回测、接入限制。

没有实际在 TradingView 编译时，明确注明尚未编译验证，不声称已编译或已实盘验证通过。

详细可执行模板与映射示例见 [开发提示词](PINE_INDICATOR_DEVELOPMENT_PROMPT.md)，实际执行能力见 [当前架构](../ARCHITECTURE.md)。

## 7. 后续协作方式

以后用户只需提出类似“开发一个超级趋势回踩指标：……具体规则……”的需求。
开发者先加载本规范和现有模型声明，自动沿用公共接口与交付要求。
不要求用户重复提供本规范、粘贴完整提示词或填写已知通用规则；仅对本次策略中影响结果的实际缺失或冲突进行针对性确认。

用户明确提出的新要求优先。接口发生有意变更时，同步维护本规范、详细提示词、映射与相关执行/回测测试，说明兼容处理。
