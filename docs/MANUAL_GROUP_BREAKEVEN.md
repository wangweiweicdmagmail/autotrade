# 执行监控：手动整组保本

在执行监控的执行实例行点击 **整组保本**，确认策略模型、实例、标的、数量和实际成交均价后提交。按当前交易组的实际余仓成交成本加权均价，将关联保护止损单统一收紧至成本（目前沿用执行模型的两位小数价格精度）。已有更有利止损保持原值。

这与现有自动整组保本的成本口径一致，不是每笔建仓分别移至自己的成本。不含佣金、滑点或跳空影响，不保证平仓净收益为零。自动保本门槛和启停参数不变，手动操作不恢复暂停的新入场。

## 状态与并发处理

- 只处理当前模型、执行实例、标的和交易组；确认请求携带交易组 ID、数量、均价。后端重新核对，归属或持仓变化返回冲突，要求刷新重试。
- 有待成交入场、未确认成交、未完成减仓、恢复待核验或正在退出时拒绝操作。已结束实例不显示保本按钮；已至成本或更有利时显示禁用的“已至成本”。
- 确认弹窗开始即防重复点击；执行期间阻止该交易组新增入场和自动保本重入。改单复用订单操作协调器，退出与撤单仍按既有优先级处理。
- 逐笔返回成功、保持原止损和失败的结果；部分失败明确提示核对订单明细。已成功收紧的止损不回退，可在核对后重试。
- 按钮和提示不代表券商已经确认保护；实际生效价格、数量与状态以订单回报为准。

## 实现与验证

接口：`POST /api/auto/instances/{symbol}/breakeven?strategy=...&instance_id=...`，沿用交易员权限，正文为 `group_id`、`qty`、`avg_cost`。执行引擎复用实盘适配层的止损修改操作，不另建独立订单链路。

隔离回归：Python 完整回归 456 项通过、13 项跳过、4 项 live 排除；整组保本专项共 15 项通过，包含余仓加权均价和关联订单缺失拦截。前端 `npm test` 14 项通过，包含对象归属、重复点击、取消、演示禁用、状态拦截和部分失败提示。测试仅使用内存券商及临时状态，不访问生产账本。
