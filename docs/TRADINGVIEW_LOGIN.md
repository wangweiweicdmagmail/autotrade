# TradingView 首次登录引导

2026-11-22：首次克隆项目后，不再需要手工提取 Cookie 或运行 `dump_creds.py`。此流程只配置行情访问，不提交任何交易订单，也不修改用户已有的 TV 图表。

## 用户操作

1. 安装项目依赖后照常启动控制台，例如 `./run_console.sh`（默认 dry-run）。
2. 本机没有完整的 `service/creds.json` 时，加载页显示“请先完成 TradingView 登录”，并说明行情尚未开始订阅；不会用 `0/54` 表示正在加载。
3. 项目专用 Chrome 准备好后，自动打开 TradingView 登录页。用户登录自己的账户，验证码和双重验证均在 TV 页面完成。也可点击“打开专用 Chrome 登录页”重新打开已有登录页；不会导航或重载图表。
4. 后台约每三秒检测一次登录会话，发现完整的 `sessionid` 与 `sessionid_sign` 后，自动保存到本机。
5. 保存成功后自动启动行情采集，加载页恢复真实的 K 线、订阅和确认指标进度。数据就绪后进入控制台，无需重启或再运行脚本。

关闭自动打开浏览器时，不会因等待登录而反复启动 Chrome；本机按钮仍可按用户点击准备专用 Chrome。现有完整凭据继续沿用原有启动路径，不重复提取或覆盖。

## 等待与异常

| 状态 | 页面说明与处理 |
|---|---|
| 缺文件、JSON 损坏或字段不全 | 等待用户在专用 Chrome 完成登录，行情进程保持停止 |
| 专用 Chrome 未启动、页面未就绪 | 显示等待浏览器；后台继续检测，用户可用按钮打开登录页 |
| 尚未完成登录／验证码 | 保持登录引导，不把此等待计作行情故障 |
| 本地写入失败 | 提示检查项目目录写入权限，自动重试；没有成功保存前不启动行情 |
| 凭据已保存，Node 进程未能启动 | 明确提示检查 Node 运行环境，保留已保存会话并重试 |
| 正常订阅后的网络／指标错误 | 沿用原有行情健康与恢复机制，不将普通网络故障解释成需要替换账户凭据 |

登录等待不计入行情启动的 240 秒诊断期限；`restart_live.sh` 也单独显示登录状态，不在用户登录期间循环打印 `0/54` 或耗尽行情检查期限。它没有降低指标就绪门槛，登录成功后仍须等原有完整性检查通过。

首次引导检测的是会话文件完整性与浏览器 Cookie 是否齐全，不单独承诺会话仍被 TV 接受。有完整文件但已在 TV 服务端失效的会话，仍由现有授权／网络诊断报告；本次不根据普通超时自动覆盖完整文件。

## 本机和远程客户端

TV 登录属于**运行 AutoTrade 的服务器电脑**。远程访问控制台时可以看到登录进度，但不能触发服务器的 Chrome 登录操作，也不会上传或提取远程设备的 Cookie。远程图表扩展绑定与服务器行情授权相互独立。

- `GET /api/startup` 新增 `tv_login`：`state`、`required`、`detail`、`local_actions`，只包含流程状态。
- `POST /api/startup/tv-login` 仅允许本机请求，并要求 `X-Autotrade-Action: tv-login`；它只打开登录页，不接收凭据内容。
- CDP 仅连接配置的本机调试端点，拒绝远程地址；精确匹配 TradingView 域名，在 TV 页面读取对应 URL 的 Cookie，不退回其他网站或普通浏览器。
- 不完整、过期、跨域拼接、分区或存在歧义的 Cookie 不保存。页面、接口与日志都不返回 Cookie 值。

## 保存和代码边界

凭据用原子替换写入 `service/creds.json`，临时文件从创建起就是 `0600` 权限，写入并刷新成功后才替换目标。失败保留原文件并清理临时文件。正式文件、旧脚本临时文件及本次私密临时文件均在 Git 忽略规则中，不能通过功能提交发布。

| 模块 | 职责 |
|---|---|
| `controller/tv_credentials.py` | 本机 CDP、Cookie 校验、打开登录页和原子保存 |
| `console/services/tv_login.py` | 等待登录、恢复采集、错误状态和任务退出 |
| `console/services/lifecycle.py` | 登录阶段、就绪判断及启动／退出编排 |
| `engine/realtime_collector.py` | 使用同一凭据路径启动原有 Node 行情进程 |
| `console/static/loading.html` | 登录引导、本机按钮及登录后真实加载进度 |

`RuntimePaths.tv_credentials_path` 可以显式指定凭据路径；独立临时数据目录默认使用自己的 `tv_credentials.json`，测试不会读取或覆盖生产凭据。登录协调器只在缺少完整文件时运行，保存并启动后结束轮询；它不修改策略模型、执行模型、券商连接设置或订单账本。
