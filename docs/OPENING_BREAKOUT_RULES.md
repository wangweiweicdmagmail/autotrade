# 小区间突破：信号与执行规则

规则版本：`opening-breakout-2026-11-05`。本文件为当前生效口径，替代研究过程中的候选参数。时间均为美东时间，K 线时间统一指开盘时间。

## 1. 模块边界与数据源

突破与 EMA 回踩分别使用自己的规则。本功能沿用现有 Python 组合信号适配器：由 Pine 提供小区间、EMA7 和斜率，Python 组合蜡烛形态过滤，人工批准后由订单管理模块执行。它不是新注册的 Pine Entry_Signal，不把以下退出或过滤规则自动套到 EMA 回踩执行实例。

- 区间：5M 进攻区域 Pine 输出 `opening3High/opening3Low`，即常规开盘 09:30、09:35、09:40 三根 K 线整体最高/最低点；09:45 后固定。
- 行情：5 分钟 OHLC。实体基线允许盘前预热，不等到 10:00 才开始。
- EMA7：已注册 `ema9_pyramid` 模型的 `e9.ema_9`，保留旧字段名，读取 Pine 实际参数为 7 的输出，不用 Python/Node 从价格另算 EMA7。
- 斜率：同模型 `EMA_Slope_ATR` 映射 `e9.ema_slope_atr`。当前 Pine 定义为 `(ema7[1] - ema7[5]) / ATR[1]`，覆盖四个 5 分钟间隔（20 分钟），不是每根斜率、角度或百分比。以信号 K 线时间上的 Pine 输出为准；这个 plot 自身使用已完成的历史值。
- 价格空间 ATR：取同根 Pine 趋势指标 Wilder ATR(10) 与最近 10 根 TR 的简单均值中的较小有效正值。TR = max(最高−最低, |最高−前收|, |最低−前收|)，包含信号 K 线；若仅一种有效则用该种。两者都无效时等待补齐。空间 ATR 与斜率 plot 中 EMA 模型的 ATR14 不混用。
- 实体基线：对历史 `abs(close-open)` 做 EMA10，alpha=2/11，十根均值初始化；排除信号 K 线，近期权重更高。信号实体不再强制超过 1 ATR。

采集器将前根极值、前三根各自的 Pine EMA7、当前 Pine 斜率连同时间戳导出。所需数据缺失或错位时不把它当作 0，不推进该根扫描游标，等待补齐；不会用未来数据填补。

## 2. 信号条件（必须同时满足）

记信号开、高、低、收为 O/H/L/C，实体中点 M=(O+C)/2，区间上/下沿 U/D，空间 ATR 为 A。

| 条件 | 多头 | 空头 |
|---|---|---|
| K 线方向 | C > O | C < O |
| 实体推动 | C−O > 此前实体 EMA10 | O−C > 此前实体 EMA10 |
| 收盘突破距离 | C ≥ U+0.7A | C ≤ D−0.7A |
| 起点距离 | abs(L−U) ≤ A | abs(H−D) ≤ A |
| 单独上影线比例 | (H−max(O,C))/(H−L) ≤20% | 同左 |
| 单独下影线比例 | (min(O,C)−L)/(H−L) ≤20% | 同左 |
| 中点越过前根极值 | M > 前根最高价 | M < 前根最低价 |
| Pine 归一化斜率 | EMA_Slope_ATR >1.5 | EMA_Slope_ATR <−1.5 |

实体基线、中点、斜率使用严格不等号；0.7 ATR、1 ATR 距离与单侧 20% 影线允许相等。上下影线分开判断，未采用“实体超过全长90%”的旧候选规则。无有效振幅、价格非法或中点取到美分后止损非法，不产生信号。

另有两个历史过滤：

1. **前 3 根无实体穿越 EMA7**：每根分别计算 `(open−其自身PineEMA7)×(close−其自身PineEMA7)`，任何一根 <0 即排除；=0 只算触碰，不算穿越。此条件未限制为开盘后，因此 09:45 的信号恰好检查 09:30/35/40。
2. **前 4 根无逆向反包**：排除信号本身，只检查常规开盘之后的 K 线，且构成反包的两根都须属于常规时段。多头排除“前阳线后阴线，阴线收盘 < 前阳线开盘”；空头排除“前阴线后阳线，阳线收盘 > 前阴线开盘”。相等不算反包；09:30 不与盘前配对，顺突破方向的反包不排除。

## 3. 时间窗口、首次信号与人工预约

- 工作日从 09:45 K 线开始检测。**10:30 起停止下单**，因此最后可执行的信号 K 线开盘为 10:20、收盘为 10:25；10:25 K 线收盘正好 10:30，跳过。
- 同一股票每天只保留第一个满足全部条件的突破信号，多空共用一次机会。未预约、满仓跳过、方向门禁拒绝或提交失败后，不把后面的 K 线当作新的首次信号。
- 根内首次达标显示预选，用户可预约或撤销。价格变化后不达标则暂时失效；预约不等于提前下单。最终仍以该根收盘的全部条件和原预约方向一致为准。
- 不曾人工预约的信号不会自动开仓。刚确认的信号也可人工点击市价开仓；服务端仅接受收盘后的 20 秒窗口，过时不追单。
- 收盘数据允许最多 20 秒补齐，超时、当前 K 线未切换、原方向不符或不满足条件就失效。等待风控和串行下单后再次检查截止时间，不能排队越过 10:30 补发。
- 同批预约按信号开盘时间、实体/ATR 降序、标的名排序提交；这不是收益排序，也不绕过账户风控。
- 人工确认仍保留开盘十分钟后的慢速行情警示；不受普通手动限价路径替换。现有 SuperTrend 同向门禁、做空总开关与禁止自动策略持仓手动加仓规则继续生效。
- 重启清空内存预约，**不自动续约或补单**。通过已保存订单记录阻止同股同日重复入场；历史扫描可重建首次信号，但历史信号不能过期入场。

## 4. 委托、风险、保护与退出

1. 收盘确认后使用 **MKT 市价父单 + STP 保护子单**。实际入场价来自券商成交，信号收盘价只作参考；滑点不保证为 0。
2. 初始止损固定为 `round((O+C)/2, 2)`。以触发观察价到止损的距离计算股数，单次风险预算代码固定 **700 美元**，仍受最大股数、仓位比例、账户总风险等限制（当前账户总风险预算 3000 美元）。不能承诺五笔都能同时成交。
3. **最多同时 5 笔突破订单**，包括待成交、有仓位和正在退出的批次；未知受理结果仍占位。此上限针对突破批次，其他执行实例仍受原账户风控。串行下单锁内检查容量和同股同日账本，防止并发穿透。
4. **取消突破的 1R 自动保本**，不按成本收益达到1R提前移动止损。普通交易原有自动保本不改。
5. 入场所在的第一根 5 分钟 K 线收盘后，把止损提高/降低到**原信号 K 线收盘价**，而不是下一根开盘价或成交均价。不严格等待300秒。以最早券商成交时间定位入场 K 线，缺失时才回退已记录入场时间；目标与时间锚点持久化，重启不重新计时。
6. 已有止损更有利就保留；现价已穿过新目标，走安全平仓链路，不挂一个越过现价的新保护单。这只是接近保本，成交滑点、手续费和跳空仍可造成亏损。
7. 新版本突破订单在**入场第三根 K 线收盘**退出（约15分钟；例如09:50入场，10:05退出）。保护/退出需新鲜行情；断流或断线会延后，不能保证在墙钟截止时成交。已有券商 STP 持续保护。
8. 停损、定时退出、手动退出共用逐批次订单操作协调器，按真实余仓处理。保护单已成交时不另发全量退出；不确定受理状态不盲目重发。部分退出未核对完成时先等待核对。

新版本标记只写入新订单。旧订单不重新定量、不批量把原止损改成中点，也不补加第三根退出；原有信号收盘保护继续兼容。启动/发布本修改不自动交易。

实时与离线筛选统一调用 `engine/opening_breakout.py` 的 `CURRENT_RULES`。历史试验用显式 `BASE_RULES` 或独立参数，不覆盖现行规则。

离线复现（只读冻结行情，不连接券商）：

```sh

PYTHONPATH=. python exports/review-data/2026-11-04/replay_signal_open_close.py --current-rules --day 2026-11-02 --cache-dir exports/review-data/2026-11-02
```

输出 `breakout_signals_current_v1.json` 和 `execution_replay_current_v1*`。回放以后一根开盘模拟市价成交，枚举5分钟OHLC的先高后低/先低后高顺序，持仓上限5笔、同刻先退出再入场、第三根收盘退出。无法完整复原根内行情、预约时点、真实排队、滑点和券商回报，因此数值回放有效不等于实盘策略验证通过，更不证明未来盈利。研究的15分钟退出是本版本明确采用的执行条件，不是系统对所有策略的默认行为。
