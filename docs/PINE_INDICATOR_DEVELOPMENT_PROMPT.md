# 新 Pine 策略指标开发提示词

> 本文是 [Pine 指标长期规范](PINE_INDICATOR_CONTRACT.md) 的详细执行模板。
> 在本项目中开发新指标时，由开发者根据根目录 `AGENTS.md` 自动加载，不要求用户再次复制提示词。

适用于本项目后续策略模型开发。依据首个模型 **EMA9-ST-ATR 的现有导出接口**和公共执行器契约整理，未假定已获得其完整 Pine 源码。

现有 EMA9-ST-ATR 指标无需改名或修改输出。以下为新指标推荐的统一标题，接入时通过字段映射兼容。

| 公共属性 | 新指标推荐 plot 标题 | 数值与含义 | EMA9-ST-ATR 当前输出 |
|---|---|---|---|
| 入场信号 | `Entry_Signal` | `1`=存在入场信号；`0`=无信号 | `Touch_EMA9` |
| 方向 | `Direction` | `1`=多；`-1`=空；`0`=中性/未知 | `Direction` |
| 入场参考价 | `Entry_Price` | 正的绝对价格，策略参考线，非挂单限价 | `EMA_9` |
| 多头止损 | `Long_Stop` | 正的绝对价格 | `Long_Stop` |
| 空头止损 | `Short_Stop` | 正的绝对价格 | `Short_Stop` |
| ATR 辅助值 | `ATR` | 所用 ATR；策略不使用时可为 `na` | `ATR` |

前五项是现有公共执行接口的必需映射；ATR 为建议保留的辅助输出。标的、周期和 bar 时间由采集器读取，不需要额外绘制一个时间 plot。

## 可直接复制的完整提示词

```text
你是一名 Pine Script 指标开发工程师。请根据我提供的策略规则，开发一个可供外部自动执行系统读取的 TradingView 策略指标。

【一、项目边界】
1. Pine 指标是策略模型：完整实现行情计算、入场条件、方向和策略止损。
2. Python 项目是执行模型：读取指标数值，进行校验、去重、风险定量、下单、成交处理、保护单与恢复。
3. 第一个已接入模型是用户自定义 EMA9-ST-ATR。新指标应复用其公共输出语义，不需要复用其均线参数、入场条件或金字塔规则。
4. 使用 Pine Script v6 的 indicator()，交付完整指标源码。除非另有要求，不用 strategy() 或 strategy.entry() 代替数值导出。
5. 不要求外部程序重新计算技术指标、识别图形、读取标签文字或依据颜色猜测信号。

【二、本次策略规则——从本轮需求和项目上下文提取】
以下是策略信息清单，不是要求用户重新填写的表格。已有信息直接沿用；只确认影响结果的实际缺失或冲突。
- 指标名称：……
- 目标市场、图表周期和交易时段：……
- 使用的指标及参数：……
- 多头方向成立与失效条件：……
- 空头方向成立与失效条件：……
- 多头入场条件：……
- 空头入场条件：……
- 入场参考价/挂单价的计算方式：……
- 多头初始止损公式：……
- 空头初始止损公式：……
- 无信号期间是否继续输出跟踪止损，以及其公式：……
- 触发时机：实时触发 / 收盘确认（必须明确选择）
- 信号触发后，入场参考价与止损是当根锁定还是继续更新：……
- 其他过滤、冷却或失效条件：……

若规则存在影响交易结果的缺失或冲突，先列出需要确认的问题。不要擅自补入未要求的过滤、保本、加仓或止盈规则。

【三、统一数值输出契约】
在全局作用域固定声明以下六个 plot，title 必须完全一致：

1. Entry_Signal
   数字 1 表示当前存在可执行的入场信号，数字 0 表示没有。
   多空都用 1，具体方向由 Direction 给出，不能用 -1 表示空头入场。
   Pine 内部 bool 必须转换成数值后导出。

2. Direction
   数字 1 表示多头方向，-1 表示空头方向，0 表示中性、未知或尚未就绪。
   它是策略方向状态，不是入场脉冲。没有入场信号时，仍应输出策略当时的方向。
   不要在每个没有信号的 bar 都机械地将方向清零。
   当前执行器会用确认后的相反方向触发退出；Direction=0 本身不代表平仓。

3. Entry_Price
   输出策略给出的计划入场参考价，单位为标的的绝对价格。
   不输出 ATR 距离、百分比或没有说明的相对偏移。
   价格由本策略规则决定，不必等于 close，也不必是 EMA。
   交付说明明确现有公共执行路径使用市价 MKT 入场，并附带 STP 保护止损；Pine 参考线不作为挂单限价。数量按触发时观察价与止损距离估算，实际成交取券商回报，可能存在滑点。其他订单语义需要明确扩展执行契约。

4. Long_Stop
   输出多头的绝对止损价。
   当 Entry_Signal=1 且 Direction=1，必须满足 0 < Long_Stop < Entry_Price。

5. Short_Stop
   输出空头的绝对止损价。
   当 Entry_Signal=1 且 Direction=-1，必须满足 Short_Stop > Entry_Price > 0。

6. ATR
   输出本策略使用的 ATR。若不使用 ATR，可输出 na 并在说明中注明。
   不为了填充 ATR 字段而额外增加入场过滤或改变策略。

对于单向策略，仍声明全部六个 plot；不支持的一侧止损输出 na。
价格按 syminfo.mintick 的有效精度处理，取整后再次校验入场与止损的严格大小关系。
一旦入场所需数据未就绪、价格无效或止损方向错误，Entry_Signal 必须为 0，不得发布不完整交易计划。

【四、图表显示和外部导出】
1. 所有协议输出用 plot() 导出，display=display.data_window，offset=0。
2. plot 标题使用上述固定 ASCII 标题；不使用中文、空格、动态标题或重名。
3. 标题和语义作为稳定接口；升级指标时不要随意更名、删除、改含义或改变取值编码。
4. 导出覆盖所有有意义的历史 bar 和实时 bar，不得仅在 barstate.islast 时输出。
5. 图表线条、信号箭头和标签可以自由设计，但必须与同一套核心计算结果一致。
6. 隐藏图表装饰不能同时关闭协议导出。外部系统以数值为准，alertcondition() 仅为可选增强。

【五、实时、确认值与信号持续时间】
1. 当前执行系统从实时快照读取入场信号，上一根确认快照用于方向反转和止损管理。
2. 实时模式不能只输出一个 tick 的短暂脉冲，也不要只在 barstate.isnew 时发布信号。
   明确说明信号在当根 bar 内如何保持、何时失效，以及是否会在同根反向时清除。
   优先采用可由 bar 数据表达的持续条件；若需要 varip 锁存，必须说明历史数据无法完整复现该根内过程。
3. 入场信号为 1 的同一快照中，方向、入场价和对应止损必须构成同一个有效计划。
4. 不需要指标等待真实成交或查询订单状态。Pine 不知道 IBKR 的实际成交价、数量、成本和持仓，不能把理论成交当成真实成交。
5. 若我选择收盘确认入场，明确标注它需要执行器消费确认入场信号。
   不能只给 Entry_Signal 增加 barstate.isconfirmed 就宣称已兼容当前实时入场消费方式。
6. 不把上一根的信号偷偷搬到下一根，不使用绘图 offset 将信号显示在实际尚未知晓的位置。

【六、止损后续输出】
1. 入场信号出现时，对应止损是本笔计划的初始保护价。
2. 如果本策略提供持续跟踪止损，说明 Long_Stop/Short_Stop 在无入场信号时的含义与更新时点。
3. 现有 single_entry 执行配置在成交后按确认值跟随止损，只允许收紧；na 或 0 不代表撤销已有保护单。
4. 不利用当前盈利侧的跟踪止损错误地发布新入场计划；新入场仍必须通过初始止损方向校验。
5. 新指标不要自行套用 EMA9 的 3-2-1 加仓、2R 解锁或 3R 保本。这些现有规则属于显式兼容执行配置，不是所有策略的默认条件。

【七、历史一致性与重绘说明】
1. 禁止未来数据泄漏、事后将信号回填到过去，以及把后续确认的 pivot 当成当时已知信号。
2. 区分“实时未收盘值变化”与“收盘后的历史信号重绘”，不要承诺二者都不存在。
3. 若使用 request.security()，解释高周期值何时确认。禁止未正确移位的 lookahead_on 偷看未来；需要已确认高周期值时采用对应官方安全写法。
4. 所有阈值与信号应能根据当时已知数据解释。说明信号触发时的价格/止损与最终收盘历史值是否可能不同。
5. 仅 OHLC 回测无法确定根内触线、成交和止损的真实顺序；varip 锁存也不能凭历史 OHLC 完整还原。必须如实说明限制。

【八、当前接口不能表达的能力】
1. Entry_Signal=0 表示不新开仓，不等于撤单或平仓。
2. Direction=0 不等于强制平仓，止损 na 不等于移除保护。
3. 独立退出信号、分批止盈、挂单撤销、复杂订单类型等不是当前五个核心属性自动支持的能力。
   若本次策略需要这些能力，单独列出输出扩展与执行端接入要求，不能声称增加一个 plot 就会自动执行。

【九、交付清单与自检】
请按顺序交付：
A. 策略规则与时间语义说明，明确所有必要假设。
B. 可直接粘贴到 TradingView 的完整 Pine v6 指标代码，无伪代码或未定义变量。
C. 六个导出属性的名称、类型、取值、无效值及更新时机。
D. 对应本项目 pine_strategies.json 的模型声明片段：包括 id/name/indicator_id、快照键、plots、fields、execution_profile。
   未发布的真实 indicator_id 留为待填写，不编造可用 ID；新模型默认选择 single_entry，除非明确要求并确认了其他执行配置。
E. 多头信号、空头信号、无信号但有方向、未就绪、止损取整后非法、实时信号失效、确认方向反转等场景的自检表。
F. TradingView 编译与图表检查步骤，以及实时/历史差异和执行端接入限制。

如果没有实际在 TradingView 编译运行，请明确写“尚未在 TradingView 编译验证”，不要声称已经编译或实盘验证通过。

最终目标：更换 Pine 策略与字段映射即可复用现有执行系统，不需要在 Python 中重写本策略的行情判断。
```

## 新指标的映射示例

以下仅是接入声明示例，未向运行配置注册新模型。真实指标 ID 应在发布并获得访问权限后填写。

```json
{
  "id": "new_model",
  "name": "新策略模型名称",
  "indicator_id": "USER;REPLACE_WITH_REAL_INDICATOR_ID",
  "realtime_key": "new_model",
  "confirmed_key": "new_model_c",
  "plots": {
    "entry_signal": "Entry_Signal",
    "direction": "Direction",
    "entry_price": "Entry_Price",
    "long_stop": "Long_Stop",
    "short_stop": "Short_Stop",
    "atr": "ATR"
  },
  "fields": {
    "entry_signal": "entry_signal",
    "direction": "direction",
    "entry_price": "entry_price",
    "long_stop": "long_stop",
    "short_stop": "short_stop"
  },
  "execution_profile": "single_entry"
}
```

现有 EMA9-ST-ATR 继续通过 Touch_EMA9/EMA_9 映射到公共属性，无需为了统一标题而修改其已发布接口。
