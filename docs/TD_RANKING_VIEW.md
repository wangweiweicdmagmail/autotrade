> 本页已被用户后续要求替代，仅供历史追溯。当前只保留趋势榜，以一分钟close相对VWAP确定开仓方向，提供市价／VWAP限价，不使用TD或大盘准入，见[当前开仓规则](CLOSE_VWAP_ENTRY.md)。

2026-11-24后续开仓规则见[个股TD基本过滤](BASIC_TD_ENTRY.md)。TD榜与趋势榜都保留各自前十范围，开仓技术方向只看个股最新确认TD；取消大盘TD同向和个股位置门槛。下文榜单筛选／排序算法不变，旧开仓条件已被替代。

2026-11-24。保留原30/50/20趋势评分、前十准入和TV稳定席位，新增独立TD观察榜。用户随后明确要求两个榜单都可开单。当前为v2：每笔手动请求显式携带`candidate_ranking=trend|td`，分别按对应前十名单复核；TV整组席位继续沿用趋势榜，切换视图不修改全局交易模式。

## TD 榜规则

- 取当前已接纳一分钟收盘快照中NAS100、SPX500的TD。2026-11-24用户改为任意一个指数同向即可：任一>0支持多头，任一<0支持空头；一正一负时同时支持两种方向，两者都为0时等待方向。指数TD缺失或错分钟则等待数据。
- 在全股票池中筛选同方向的有效确认TD，按TD绝对值从大到小取十名。相同TD按完整标的代码排序，避免修订或遍历顺序造成闪动；无需达到±3。
- 沿用原趋势榜的参考标的排除范围：两个指数、WTI、QQQ、SPY、SMH、XLB、XLP、XLU、XLV不参与个股排名。两指数仍在顶部固定显示。
- 候选不必已经进入趋势榜，也不引入趋势评分、EMA斜率或乖离的重复计分。数据缺口、未就绪、TD缺失／重复／错周期的股票明确列入`missing`，不用旧分钟补数。
- TD复用现成确认输出，Python只筛选、排序，不重新计算指标；股票extended、指数default及原预热规则保持现状。

## 接口与一致性

`GET /api/market-rhythm`在原响应中新增`td_ranking`：

```json
{
  "version": 2,
  "model": "beta_td_magnitude_v1",
  "scope": "candidate",
  "as_of": 0,
  "snapshot_id": "与ranking_snapshot.id相同",
  "status": "ready|neutral|waiting",
  "direction": 1,
  "td_rule": "any_index_same_sign",
  "allowed_directions": [1],
  "beta": [],
  "ranks": [],
  "missing": [],
  "sort": "absolute_td_desc_then_symbol"
}
```

`as_of`实际值为确认分钟收盘时间戳，例中0只是占位。`allowed_directions`声明当前TD支持的方向；同时支持多空时为`[1,-1]`且`direction=0,status=ready`，不能把direction=0单独解释为等待。每行`direction_sign`取该股票TD的正负号。两种方向合并按|TD|排序，共十名，不分别扩展为二十名。`ranks`每行包含标的、TD榜名次、方向、TD计数、K线开盘时间`bar_time`、`confirmed_at`和原趋势名次`trend_rank`（未入趋势榜时为null）。原`ranks`和`tracks`继续表示趋势榜；新增`td_tracks`携带TD前十的真实确认K线与TD。趋势订单及自动／信号订单仍用趋势名单，明确来自TD榜的手动市价单使用TD名单；TV席位继续沿用趋势榜。

两榜由同一个`MarketRhythmReader`已冻结快照导出。同分钟迟到修订不换榜，新分钟未齐／评分待齐则两榜均保留上一批；重启恢复同一内容ID。TD榜从完整`series`投影，不仅对已返回的十个趋势`tracks`重新排序。排名依据仍冻结；最新TD标签和开仓另用[逐标的确认数据](LIVE_CONFIRMED_TD.md)。旧后端缺少新确认契约时须加载新版，不能拿未收盘TD替代。

## 界面与加载

左侧提供“趋势榜／TD榜”按钮，选择按客户端来源和交易员保存在独立的`rhythm_rank_view_v1:*`偏好中，不改写TV展示席位偏好或服务端交易配置。两个固定指数在两种视图中位置不变。

两个榜单均显示“开仓”。TD按钮打开带“TD榜市价”标题的手动卡片，方向来自个股确认TD，要求与NAS100、SPX500中至少一个确认TD同向；不使用趋势段方向替代。TD标的不必同时进入趋势榜。点击仅打开卡片，最终发单仍需用户操作。

用户已明确确认取消TD入口的个股VWAP区间／中线及EMA9位置过滤，只按个股TD与至少一个指数TD同向确定方向。大盘绝对趋势禁反向已按用户要求暂时关闭；任一指数TD同向、报价新鲜度、常规盘窗口、风险预算、止损、重复建仓和持仓保护继续生效。代码中的`TD_POSITION_FILTERS_REQUIRED=False`及准入快照的`ema9_required=false`／`vwap_direction_required=false`明确声明当前规则，界面不再列出个股位置检查。服务端及最终发单复核均将TD订单的`vwap_outside_only`规范为false，旧客户端发送true也不会重新加上外轨过滤。趋势榜及自动／信号订单的原位置过滤保持有效。

新请求字段`candidate_ranking`默认`trend`，只有`td`与`trend`两个合法值。TD来源只允许明确的手动MKT＋STP入口，不允许强制方向、混用策略信号／自动策略、限价单或回退至旧趋势准入。服务器计算方向、止损和数量，订单管理模块在风险等待及受理意图之后再次调用同源准入。

WS分别发布`entry_candidates`与`td_entry_candidates`，两份快照共用已接纳排名成员与同一次独立确认读模型。整榜不再因为超过120秒拦截，时效检查限所选股票和两个指数。来源在开仓卡片、确认与发单期间必须保持一致；客户端切换来源、大盘TD转向、离榜、数据失效均阻止本次发单。订单证据保存`candidate_ranking`及`candidate_admission.ranking_mode`，重启不会把历史TD订单误标为趋势订单。

新增API需要重启后端加载，随后刷新页面。第一版没有为开发自动重启正式服务、修改生产持仓或向券商提交订单。历史TD榜可依据归档一分钟K线和固定TD契约重新计算；新增观察投影本身不作为当时已下单或已获准入的证据。
