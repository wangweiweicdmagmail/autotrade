## 触发口径

- 在登记的美东上市日09:30至16:00之间，首次观察到有效正成交价、正成交量与当日新鲜时间，立即生成提醒。不等第一根K线收盘，也不等EMA、ATR、ST或PineTS预热。
- 主通道是TV常规盘Quote的`lp`、`lp_time`、`volume`。买卖盘价、发行参考价、缺时间或零成交量的占位数据不能触发。
- 备用通道是独立的常规盘1分钟Chart，只需1根实时形成中的OHLCV。首笔成交在分钟中途出现也可触发；备用时间明确记作`bar_open`，不当作交易所逐笔成交时刻。
- 时间必须在当日常规盘，价格时间距观察不超过90秒。Python接收边界另核对观察延迟不超过30秒，拒绝跨日、未来和明显过期的历史预载。
- 所谓“首价”是本系统数据源首次观察到的有效成交价，不能保证就是交易所开盘竞价的第一笔价格。晚启动或数据源有延迟时尤其不能冒充精确首笔成交。

## 数据链路与隔离

`service/ipo_watch.js`复用现有TV WebSocket客户端，增加1个轻量Quote市场与1个单根分钟Chart，不注册Pine指标。IPO缺少历史是正常等待状态，备用图表无数据或沉默会单独重试，不使用常规股票重建次数上限。

启用时，IPO标的只加入独立监测名单，不强行加入常规策略股票池、指标就绪率、VWAP整批齐备、六宫格候选或回测加载门槛。它没有历史数据时不会卡住其他标的。IPO消息单独送给`RealtimeCollector._accept_ipo()`，不更新普通行情的内容、传输或K线新鲜度时钟，不能用新股报价掩盖主行情中断。

Python `IpoAlerts`在收到有效消息时直接记录，不依赖有没有浏览器连接，也不等待账户/TWS查询。控制台WebSocket快照的`ipo_openings`与只读`GET /api/ipo-openings`提供状态和已确认事件。

## 去重与追溯

首次观察先提交独立的`ipo_alerts.sqlite3`（非执行账本），键为`ipo:完整标的:美东上市日`，提交后才对前端发布。行情重连、同日后续价格变化与服务重启不覆盖原首价。事件同时记入`events-YYYYMMDD.jsonl`，类型为`ipo_first_trade_observed`，包含价格、成交量、源时间、观察/检测时间、来源及时间精度。

暂时无法写盘时，内存保留首次观察和原检测时刻，后续重试不会用更晚价格替换；未知版本或损坏状态明确报错，不静默删除或当成空状态。

前端每个客户端按事件ID持久化去重；已打开的其他同源标签页也会重新读取去重记录。新事件进入语音优先队列并显示常驻通知，播报“新股A N T已开始交易，首次收到成交价格……美元”。页面重连可补播最近120秒内的新事件，超过窗口只显示记录，不把旧事件当成刚开交易。不同设备各自提醒，不自动全局静音其他交易员。

## 界面与验证边界

有当日IPO监测任务时，顶栏显示IPO状态，例如“IPO ANT·等待首价”；名单为空时不显示该入口。展开可查看上市日期和数据状态，并点击“测试语音”。该测试只播报“提醒已就绪，等待真实成交价格”，不会伪造ANT已经开交易，也不会生成首价事件。实际播报依赖控制台网页保持打开、浏览器允许语音且系统音量正常。

此功能只提醒，不调用任何开仓、改单、撤单或平仓接口。隔离回归使用内存报价、模拟语音对象和临时SQLite目录；实盘连接测试只读订阅真实ANT的盘前元数据，不注入虚假成交价。
