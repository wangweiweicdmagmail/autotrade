## 已确认的项目边界

1. 一个 Pine 指标是一个策略模型。入场信号、方向、入场参考价与初始止损来自指标输出。
2. Python 项目是可复用的执行模型，负责输出校验、去重、风险定量、订单与保护单、成交处理及恢复。
3. 当前第一个模型是用户自定义的 **EMA9-ST-ATR**，不是单独的 EMA9 均线。
4. 兼容标识 `ema9_pyramid`、快照键 `e9/e9_c`、指标 ID 和已有订单状态继续保留。
5. 后续超级趋势回踩等模型接入统一输出映射；本里程碑没有代替用户实现或注册第二个真实 Pine 策略。

## 兼容与边界

- `uvicorn console.app:app` 和现有启动脚本继续兼容。
- 现有 HTTP/WebSocket 路径有兼容检查，模型及实例字段采用增量扩展。
- `engine.auto_engine` 保留旧 Broker 导入，`engine.pyramid_engine` 保留旧类名。
- `main.py`、`auto_runner.py` 是历史流程，不能将其策略语义视为当前 EMA9-ST-ATR 主入口。
- 原 EMA9 金字塔、时段、保本等规则显式保留在 `ema9_legacy_pyramid` 执行配置中；本阶段没有将这些规则迁回 Pine。
- 新模型的基础配置为 `single_entry`；其他下单或退出语义需明确定义执行配置并增加契约测试。
- 旧订单缺少模型归属时仅按默认 EMA9 实例处理；恢复资料不足时暂停自动加仓。
- OHLC 回测仍是确定性模拟路径，不能证明真实根内成交时序。
- 运行态字典、账户配置隔离和存储事务化仍有后续演进空间，未把第二、三阶段标为完成。
