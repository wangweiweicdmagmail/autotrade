# 第二阶段：领域契约与订单操作协调

日期：2026-11-02。承接[第一阶段](2026-11-02-phase1.md)的模块边界与可复用执行模型。
本阶段完成公共 Pine 执行链路的领域契约、时间语义、累计成交增量与订单操作协调。
本记录是工作区交付记录，不代表已创建 Git 提交、标签或已部署生产服务。

## 1. 范围与决策边界

策略模型仍为 Pine 指标，首个模型是 **EMA9-ST-ATR**。入场信号、方向、入场参考价和
策略止损仍来自 Pine；Python 只实施既有执行配置、账户约束与订单管理。
没有新增指标逻辑、行情筛选或不同来源退出之间的业务优先排序。

覆盖 `StrategyRuntime → PineExecutionEngine → LiveBroker/SimBroker` 主链路，
以及共享 `OrderManager` 的下单、累计成交 watcher 和公开订单操作。
历史 `main.py/PositionManager`、`auto_runner.py`、独立跟单执行器没有全面迁移。
旧 OCA/对账及手工部分平仓分支继续保留，不宣称所有恢复事实均已转换为同一种成交事件。

## 2. 统一数据契约

新增 `domain/contracts.py`，仅依赖标准库，不读取配置、不加载状态、不连接券商。
类型为不可变数据对象，外部 HTTP、快照字典和 Broker 方法签名通过边界适配继续兼容。

| 对象 | 统一内容 | 已接入位置 |
|---|---|---|
| `PriceObservation` | 标的、有效价格、观察/接收时间、可选行情源时间、所在 K 线 | 实时调度与执行引擎 |
| `ClosedBar` | 标的、K 线开盘时间、周期、收盘价及可选 OHLCV | 确认调度、恢复调度、历史回放 |
| `StrategyOutput` | 模型归属、Pine 时间、方向、入场、参考价、止损、错误及确认属性 | 输出解码、实时与确认管理；原 `PineOutput` 导入仍可用 |
| `OrderPlan` | 方向、数量、入场/止损、风险参考价、预算、交易归属与审计时间 | 公共引擎、实盘和模拟适配、订单管理入口 |
| `StopAmendment` | 价格有效性、两位小数、止损只紧不松 | 实盘与模拟止损修改 |
| `FillEvent` / `FillDelta` | 累计成交、均价、接收/券商时间、订单标识、相对前次的增量 | 入场/全量退出 watcher、模拟成交事件 |
| `TradingGroupKey` | 模型 + 执行实例 + 标的 + 交易组 | 订单计划归属、执行实例 |
| `ExecutionGroupState` / `OrderState` | 交易组视图及订单状态语义 | 执行实例视图、实盘/模拟订单生命周期 |

入场价格与止损先按既有规则保留两位小数，再向下取整风险对应数量；
溢价限价单的风险参考价可独立保留。NaN、无穷、布尔值和非法方向/止损不能进入有效计划。
订单元数据新增 `order_plan` 审计信息，包含归属、信号 bar 时间、创建时间与计划风险。
实盘账户风险仍由 `RiskGate` 决定；模拟接口复用计划契约不意味着覆盖全部实盘账户风控。

`ClosedBar` 允许仅有时间与收盘价的兼容输入，不代表已经验证完整 OHLC 几何关系。
模拟仍使用原有历史极值路径，未增加成交微观结构模型。

## 3. 时间语义与确认游标

| 时间 | 定义 | 禁止混用 |
|---|---|---|
| Pine `time` / bar `open_time` | K 线起始时间 | 不能当作逐笔价格发生时间或成交后观察时间 |
| bar `close_time` | 起始时间 + 周期，当前标准调度默认 300 秒 | 不能因收到快照就假定完成 |
| `observed_at` | 采集器观察价格的时间 | 没有该字段时明确标记使用运行时接收时间 |
| `received_at` | 当前边界接收快照/成交状态的时间 | 不宣称是券商成交时间 |
| `market_time` / `broker_time` | 来源明确提供的市场/券商时间 | 缺失保持未知，不伪造 |

确认调度规则：

1. bar 或确认输出为空时等待，不消耗游标。
2. 确认 bar 不能是当前实时 bar；显式 Pine 时间必须与确认 bar 起始时间一致。
3. 正常调度游标只前进，不重复消费同一根或更旧 K 线。
4. 只有执行引擎处理成功后才推进游标，异常后下一次快照可重试。
5. 旧非空确认快照缺少时间时保留兼容；每个模型/实例/标的记录一次
   `pine_confirmation_unverified`，不把它标记为已核验时间对齐。
6. 恢复接管使用同一确认适配器；显式恢复可以重新处理当前确认 bar。

历史回测每行最终指标值按确认输出适配，沿用人工美东启动时间和启动前无订单的边界。
这只能核对给定历史输入的执行行为，不能完整复现实时根内信号、报价与实际成交先后。

## 4. 累计成交与余仓

券商 `orderStatus.filled` 是该订单累计数量，不是每轮 watcher 新成交。
`FillEvent.delta_from()` 以“当前累计 − 前次累计”计算数量增量，以累计金额差处理均价变化。

- 重复快照不重复增加/扣减持仓，累计数量回退按异常快照忽略。
- 入场累计数量与实际余仓分开保存。100 股入场后卖出 50 股，再收到累计入场 100 股，余仓仍为 50；
  后续累计入场变为 110 股，只增加 10 股。
- 价格尚未知时不编造实际成交价格；全量退出保留数量核对和等待真实均价的原有闭环。
- 从成交明细提取明确的带时区券商时间；不存在时为空，与本机接收时间分列。
- 主链路变化产生 `execution_fill` 审计，包含累计量、增量、均价、时间及交易归属。
  审计回调失败只记录错误，不驱动额外下单。
- 对账/OCA 激活保留完整入场累计基线，再按券商实际余仓封顶，避免后续重复入场快照恢复已减掉数量。

新增状态字段包括 `entry_cumulative_qty/entry_cumulative_avg`、`entry_broker_time`、
`last_fill_received_at/last_fill_broker_time`；旧文件缺失时使用默认值和已有数量恢复基线。

## 5. 操作协调规则

`execution/operations.py` 使用原有逐 lot 锁，避免增加第二套互相竞争的锁。
退出/撤单在申请锁之前登记意图，不能仅等到执行时才发现已有旧改单排队。

| 操作 | 与退出/撤单并发时的处理 |
|---|---|
| 全量退出、撤单 | 同一优先级，按到达及锁顺序核对生命周期后执行 |
| 部分减仓、止损修改、保本、入场改价/升级 | 尚未执行而被退出/撤单覆盖的命令失效，返回明确原因 |
| 已发往券商的修改请求 | 不虚构取消；等待请求结果，再执行退出/撤单 |
| 成交回报、对账事实 | 继续在订单锁下核对，不能被操作优先级丢弃 |
| 退出等待被取消或失败后的新保护请求 | 重新核对订单状态后可执行，不永久锁死保护 |

不区分人工、Pine 或风险模块的退出优先级；它们都是终止意图。
此协调器只管理同一进程内共享 `OrderManager` 的操作，不是跨进程分布式事务。

## 6. 并发建仓与迟到受理

- 账户建仓临界区覆盖风险检查、券商提交和订单登记，避免两个实例同时使用同一剩余风险预算。
- 双击/重试的两秒去重基于请求收到时间，包含等待账户锁的时间；慢券商响应不会把双击变为新请求。
- 引擎按交易组标记下单进行中，避免不同实时快照在首笔订单尚未返回时重复提交。
- 券商返回前若已要求退出，先将受理订单挂回原交易组，再完成撤单或平仓。
- 原交易组已被新组替换时，迟到订单继续归原组并退出，不被新组误接管。
- 仅“暂停新入场”保留已经提交的订单，符合现有界面语义。

账户串行化会使慢请求后的建仓等待；退出/保护使用逐订单锁，不等待这个账户建仓锁。
进程在提交期间崩溃、券商已受理但本机没有确认等跨系统故障仍依赖既有对账恢复。
