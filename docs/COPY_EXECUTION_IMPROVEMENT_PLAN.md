# 跟单执行改进方案

本方案以主端已确认的成交和余仓为跟单目标，以跟单账户的券商成交为执行结果。改造覆盖主端快照、跟单定量、订单提交、保护与退出、恢复对账和运行监控。按三个阶段实施，完成隔离回归和模拟账户验收后才进入实盘试点。

现状参考 [跟单执行器](../copy_trader.py)、[券商连接网关](../execution/ibkr.py)、[订单操作协调器](../execution/operations.py) 和 [执行账本](../execution/state_store.py)。

## 一、跟单规则与数据契约

| 项目 | 约定 |
| --- | --- |
| 跟单身份 | 主端部署 ID + 主端稳定批次 ID + 跟单账户 ID。账户或主端身份变化必须重新核对。订单引用再加动作和序号。 |
| 主端事实 | 发布明确的累计入场成交量、累计退出成交量、实际余仓、成交均价、当前保护价、退出状态和版本序号。允许重放快照，消费者拒绝倒序版本。 |
| 首次跟随 | 主端出现实际成交后才产生目标。默认跳过连接前已经存在且无本地映射的仓位。显式启用接管时仍需通过对账和风控。 |
| 分批与减仓 | 按独立主端批次计算目标。倍率和净值模式以实际成交量为基准，风险模式冻结首笔有效计算的定量基准。主端后续累计成交或减仓按冻结规则调整目标，避免行情或净值波动触发反复交易。 |
| 退出 | 主端确认退出意图时禁止该批次新增跟单入场并撤销待成交余量。主端已确认的减仓或清仓更新目标余仓。主端记录暂时缺席时保留已知状态，发起核对。 |
| 风险与价格 | 首仓仍按明确配置的限价策略执行。校验方向、报价时效、止损侧、每笔风险、股数、名义仓位及账户总敞口。保本或已越过成本的主端止损不能用一美分距离放大跟单股数。 |
| 保护 | 保护单数量以跟单账户实际余仓为准。默认只收紧止损。调整保护、减仓和退出统一协调，所有提交状态和成交状态分开记录。 |
| 独立风险事件 | 跟单保护单先成交、跟单账户人工干预或持仓无法归属时，冻结该批次自动补仓，显示待核对。 |

目标股数使用统一取整规则，部分退出按已冻结的跟随比例计算剩余目标，主端清仓时目标直接归零。保留待成交量和已成交量，计算下一笔委托前扣除方向相同的未完成订单。风险模式的冻结基准、价格偏离上限及风控参数应可审计。

## 二、阶段一：修复下单、保护和退出

| 审核问题 | 修改方案 | 验收 |
| --- | --- | --- |
| 断线被记成模拟平仓成功 | 网关区分显式模拟与实盘断线。跟单实盘路径遇到断线或意外模拟回包时保留退出意图，不修改成交和余仓。评估共享网关其他调用方并补兼容回归。 | 断线请求不会被标为已平仓，重连后按实际余仓继续。 |
| 提交等同成交 | 拆分待入场、部分成交、持仓、待退出、部分退出、已结束和待核对。按券商累计成交增量推进，成交记录按稳定执行 ID 去重。入场受理只绑定订单身份，退出受理只记录待成交。 | 未成交时收到主端退出只撤入场。成交 30 股时退出上限为 30 股，晚到成交需重新核对。 |
| 撤止损与平仓竞态 | 同一批次由操作协调器串行执行，退出优先于加仓和改单。撤销入场余量后核对最终成交，再协调保护单与退出单。优先使用经模拟账户验证的券商联动；否则等待原保护单撤销终态后按确认余仓提交退出。退出单明确失败时按余仓恢复保护。受理未知时先查明是否有活动退出单，防止两张卖单同时覆盖同一余仓。 | 止损触发、撤单回报和主动退出任意交错时，不产生反向持仓。保护缺失或状态未知时可见并告警。 |
| 受理不明与并发重试 | 将快照、定时重试和人工命令送入同一串行处理入口。每笔写操作先事务保存意图及稳定引用，后调用券商。异常、超时和断线进入待核对。仅对明确未提交或已终态且无后续成交的可重试失败，重新计算余量并生成下一次意图。 | 注入提交后超时、回包丢失和并发重试，同一意图最多创建一张券商订单。 |

状态流转以事实为门槛：意图已保存 → 订单已受理 → 部分成交或全部成交。任何一步遇到结果不明，保持原有持仓与保护记录，暂停相关自动操作。只有关联入场、保护和退出订单均确认终态且实际余仓归零，才归档该批次。

## 三、阶段二：同步、账本和恢复

1. **同步目标仓位。** 新增版本化跟单快照，逐批次同步实际入场、部分退出和全部退出，校验来源与版本。保持完整的当前批次及必要终态记录，重连后先核对完整快照。当前快照超时、主端重启或身份变化时冻结新入场。已有券商保护继续生效，已确认的退出意图按恢复规则处理。跨主机连接采用认证和加密，跟单数据只提供必要字段。
2. **独立 SQLite 账本。** 按跟单账户存放，复用现有执行账本的事务、版本检查、原子导出和单写者约束。保存主从映射、订单意图、券商订单引用、成交游标、操作结果、退出任务、风险基准和熔断状态。把 JSON 作为兼容导出。进程重复启动应在连券商前失败。
3. **启动和重连对账。** 启动先冻结新开仓，核对券商持仓、活动委托和可取得的成交。优先用稳定订单引用、券商永久订单标识与账户定位，订单号只能在作用域明确时使用。逐笔恢复父单、保护单和退出单，核对同标的多批次。账户净持仓只用于交叉校验，不能凭它猜测每笔归属。成交历史不足、状态损坏或差异未解决时进入待恢复，保留原始证据。
4. **持久化回撤熔断。** 按账户与美东交易日保存首次有效净值及阈值，重启恢复基准。熔断保持到显式解除，解除操作留痕。净值不可核验时冻结新入场，已确认余仓的保护和退出继续按安全流程处理。
5. **迁移旧映射。** 对原文件做只读备份和版本检查，导入时把旧 ACTIVE、CLOSING 和 CLOSED 作为待核验线索。以券商事实确认后再启用写入。旧版运行期间只做离线迁移演练，切换时确保单一写者。损坏文件停止迁移并报错，避免自动按空账户启动。

## 四、阶段三：控制台、告警与上线

- 控制台按账户显示主端快照时间、券商连接、对账结果、熔断状态。每笔同时显示主端目标量、跟单实成交量、剩余委托量、券商确认保护量及退出进度。状态区分已受理、已成交和待核对。
- 告警聚焦需要处理的事项。短时重连仅展示状态。实际持仓无有效保护、退出长时间未完成、映射冲突或持续断线时按账户与批次去重。恢复后结束告警。人工操作保留「暂停新入场」「重新对账」「解除熔断」。重新对账不会直接重发旧单。
- 先完成本地隔离回归，再使用独立模拟账户验证完整链路。覆盖一次收盘、一次主端与跟单端重启、一次断线重连和一次人工解除熔断。完成后只选一个跟单账户、少量标的和明确仓位上限试点，核对无未解释差异后再扩大范围。
- 异常回退优先冻结新跟单，保持券商保护并逐笔对账。确认委托和余仓归属后，决定继续新版恢复还是停用跟单。旧版无法识别新账本中的未完成意图，不能直接在仍有活动订单时接管。备份用于恢复证据，不作为覆盖当前成交记录的手段。

## 五、测试矩阵与放行条件

| 场景 | 必须满足 |
| --- | --- |
| 父单未成交、部分成交，随后主端退出 | 撤销剩余入场，只处理真实余仓。部分成交与迟到成交均有账本记录。 |
| 止损和主动退出同时触发 | 无重复退出、超量卖出或反向开仓。等待期间保护状态可核验。 |
| 提交前崩溃、提交后回包前崩溃、受理后未保存 | 重启能识别已有意图，核对后决定后续动作，未知结果不重发。 |
| 重复快照、倒序快照、断流与重连 | 目标余仓不倒退，不因旧快照开仓。恢复先对账。 |
| 主端减半、连续部分成交、同标的多批次 | 按归属和累计成交增量同步，保护数量匹配实际余仓。 |
| 实盘断线、错误模拟回包、券商拒单 | 不产生虚假成交。明确失败与未知受理走不同路径。 |
| 损坏账本、错误账户、双进程、券商成交历史不足 | 新入场被拦截，保留原始数据和可操作的恢复状态。 |
| 当日熔断后重启与跨日 | 风险基准和熔断状态可恢复。人工解除有审计记录。 |
| 停止或修改跟单配置 | 暂停入场后仍能查看和管理已有仓位。配置切换不会改变旧批次冻结的定量基准。 |

放行要求：两个 P0 和四个 P1 均有对应故障注入回归，主从快照和新旧映射迁移通过验证，模拟账户订单与账本逐笔吻合，无未解释的余仓、无裸仓、无重复委托，告警和回退流程均经过演练。独立模拟账户验证是进入实盘试点的必要条件。
