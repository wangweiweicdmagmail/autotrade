# TradingView 左右分屏界面优化

日期：2026-11-02。依据用户手动拆分后的窗口，以控制台约 1060 CSS px 宽为主要使用场景，完成全部 14 个工作区页面适配。此轮修改前端展示、导航和空值防护，不修改策略输出契约或执行规则。

## 导航与空间

主导航顺序：**执行监控 → 订单批次 → FVG 监控 → 选股 → 回测验证 → 夜盘模拟 → 研究复盘 → 系统运维**。

选股从研究复盘中移出，独立放在 FVG 监控之后；研究复盘保留盘前报告、盘前新闻、影子、收益对比和绩效。旧工作区布局若仍保存选股为研究页，切回研究时会回到有效的盘前报告页。

1060px 测量中顶栏约 75.7px，状态、账户与风险压缩为两行，连接时序展开为浮层，不再撑高顶栏。保留单排导航，超窄窗口可在导航内横向滚动。实例启动区默认只显示模型、实例、标的、首仓预算和启动操作，执行参数按需展开；各实例继续展示真实生效规则。

执行监控后续增加优先级排序：有仓位的实例置顶，其余待运行/待处理实例居中，确认本轮结束且数量为零、无关联订单、无待处理退出或恢复事项的实例置底。同一优先级保留原有相对顺序，不修改后端快照。暂停新入场但仍持仓的实例继续置顶管理，不被误标为已停止。底部停止区采用中性色、虚线卡片、“已停止 / 不再执行”标签与历史价格说明，保留订单明细入口；运行实例的常用操作继续直接显示。见 [合成实例排序与停止区截图](screenshots/split-screen-2026-11-02/instance-priority-1020.png)。1020px 截图已检查，820px、1600px 复查无整页横向溢出；`npm test` 14 项通过。

## 生效方式

后续补充：独立启动加载页也已适配分屏，移除固定 520px 窄卡片和状态详情省略；按宽度切换两列/单列，并完整展示长提示。已截图检查 [1020px](screenshots/split-screen-2026-11-02/loading-1020.png)、[600px](screenshots/split-screen-2026-11-02/loading-600.png)、[360px](screenshots/split-screen-2026-11-02/loading-360.png)，图片使用独立合成启动状态。浏览器启动增加 HTTP 可访问检查，这部分启动顺序修改需要下次重启控制台后生效；没有为了验证而重启正在运行的交易服务。

工作区和加载页的布局属于静态前端更新，使用 **⌘⇧R 强制刷新**即可加载；浏览器启动时机的后续修复涉及后端，须在下次重启控制台时加载。本轮没有重启用户正在运行的交易服务，没有操作真实 TradingView 或 TWS。
